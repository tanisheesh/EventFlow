# Deploying EventFlow

> **Live:** [eventflow-g2h5.onrender.com](https://eventflow-g2h5.onrender.com) · **Host:** Render · **Auto-deploy:** on push to `master`

For local development, see [SETUP.md](SETUP.md).

---

## 1. Architecture in production

| Piece | Runs on | Notes |
|---|---|---|
| EventFlow web app | Render | Free web service in Oregon, `python start.py`; sleeps after inactivity |
| Database | Render (local disk) | SQLite file, re-created with demo accounts on every start |
| Reqly collector | Render | [reqly-eventflow-collector.onrender.com](https://reqly-eventflow-collector.onrender.com), receives EventFlow's metrics |
| Reqly dashboard | Render | [reqly-eventflow-dashboard.onrender.com](https://reqly-eventflow-dashboard.onrender.com), public and read-only |

---

## 2. Environment variables

Set these in the host dashboard (never commit them). Names and sources are in [`.env.example`](../.env.example).

| Variable | Required | Where it's set |
|---|---|---|
| `SECRET_KEY` | ✅ | Generated by the Blueprint (`generateValue`) |
| `FLASK_ENV` | ✅ | `render.yaml` (`production`) |
| `DATABASE_URL` | ✅ | `render.yaml` (`sqlite:///eventhub.db`) |
| `PORT` | ✅ | `render.yaml` (`5000`) |
| `REQLY_COLLECTOR_URL` | ❌ | `render.yaml` |
| `REQLY_API_KEY` | ❌ | Render → EventFlow → Environment (`sync: false`): the collector's `REQLY_INGEST_KEY` |
| `REQLY_ENVIRONMENT` | ❌ | `render.yaml` (`production`) |
| `REQLY_CONSUMER_SALT` | ❌ | Generated by the Blueprint (`generateValue`) |
| `REQLY_DASHBOARD_URL` | ❌ | `render.yaml` |

The release is not configured: the Reqly SDK reads `RENDER_GIT_COMMIT`, which Render sets on every deploy.

> After changing an env var, **redeploy**. Running deployments don't pick up new values.

---

## 3. First-time deploy

1. [dashboard.render.com](https://dashboard.render.com) → New → **Blueprint** → connect `tanisheesh/EventFlow`. Render reads `render.yaml`.
2. Build command: `pip install -r requirements.txt`
3. Start command: `python start.py`
4. When asked, enter `REQLY_API_KEY` (or leave it empty to run without monitoring), then deploy.

---

## 4. Database migrations

None. `start.py` runs `db.create_all()`, which creates missing tables, and seeds the demo accounts. On the free
plan the disk is reset on every deploy, so production always starts from an empty database plus the demo
accounts.

---

## 5. Verify a deploy

- [ ] `https://eventflow-g2h5.onrender.com` loads (allow ~30s for a cold start)
- [ ] Each demo account logs in: admin, organizer, attendee
- [ ] Core flow: as the organizer create an event with a ticket type, as the attendee book and cancel a ticket
- [ ] As the administrator, **Metrics** opens the Reqly dashboard and the requests above appear for `eventflow` under the new release

---

## 6. Rollback

| Host | How |
|---|---|
| Render | Service → Events → last good deploy → **Rollback** |
| Database | Nothing to roll back: the SQLite file is re-created on every deploy |

After rolling back, note it in a commit or PR so the next push doesn't silently re-ship the broken version.

---

## 7. Monitoring & logs

- **Logs:** Render → EventFlow → Logs
- **API metrics and alerts:** [Reqly dashboard](https://reqly-eventflow-dashboard.onrender.com): latency, errors, releases and users per route
- **Dependencies:** Dependabot opens weekly update PRs and a maintenance report is emailed every week (see `.github/workflows/`)

---

## Known production limitations

- Render free tier cold-starts in ~30s after inactivity.
- Data created on the live demo is lost on every deploy or restart.
- `start.py` serves with Flask's built-in server rather than gunicorn.
